# Deck Manifest v1

This document defines the v1 deck ingest contract for local repo decks.

## Scope

- Deck models supported in v1: `standard52`
- Joker support in v1: `model.jokers` can be `0`, `1`, or `2`
- Onboarding source in v1: local manifests in `assets/decks/<deckFolder>/deck.json`
- Non-52 deck models are out-of-scope in v1 but not blocked by the schema (`model.kind` is open-ended)

## Folder Structure

```text
assets/
  decks/
    <deckFolder>/
      deck.json
      cards/
        *.svg
      .normalized/
        deck.normalized.json
        cards/
          *.svg
    decks.index.json
```

- `deck.json` is hand-maintained source metadata.
- `.normalized/` output is generated by `npm run decks:normalize`.
- `decks.index.json` is generated by CLI, not hand-maintained.

## deck.json Schema (v1)

Required fields:

- `manifestVersion`: `1`
- `deckId`: string matching `^[a-z0-9][a-z0-9-]{1,63}$`
- `deckVersion`: SemVer string (for example `1.0.0`)
- `title`: non-empty string
- `model.kind`: non-empty string (`standard52` supported in v1)
- `model.jokers`: integer `0 | 1 | 2` (optional, defaults to `0`)
- `cards`: non-empty array

Card entry fields:

- `cardId`: unique non-empty string
- `rank`: for `standard52`, one of `A,K,Q,J,10,9,8,7,6,5,4,3,2` or `JOKER`
- `suit`: for `standard52`, one of `spades|hearts|diamonds|clubs`; must be `null` when `rank=JOKER`
- `asset`: relative path to `.svg` inside the deck folder

Optional fields:

- `description`: string
- `locale.code`: locale tag (for example `en-US`, `fr-FR`)
- `locale.rankLabels`: map of rank label overrides
- `locale.suitLabels`: map of suit label overrides

Coverage rules for `model.kind = standard52`:

- Exactly one card for each canonical rank+suit pair (52 total).
- Joker entries must exactly match `model.jokers`.

## CI Validation Policy

- Any schema, coverage, or safety violation fails `npm run decks:validate`.
- Missing optional metadata (for example locale labels) is warning-only.

- `DOCTYPE` declarations (including external DTD refs)
- External URL refs in `href`, `xlink:href`, or `url(...)` (only internal fragment refs like `#id` are allowed)

## Normalization Rules

Normalization runs in CI/build tooling (`npm run decks:normalize`).

1. Validate manifest and SVG safety first; abort on any hard error.
2. For each SVG:
   - Ensure root `<svg>` exists.
   - Ensure `viewBox` is valid; if missing, derive from numeric root `width` + `height`.
   - Strip root `width` and `height` attributes.
   - Add `data-ctp-normalized="true"` on root.
3. Write normalized SVGs to `assets/decks/<deckFolder>/.normalized/cards/`.
4. Write `deck.normalized.json` containing normalized card `assetPath` values.
5. Generate `assets/decks/decks.index.json` from normalized manifests.

## CLI Command Spec

- `npm run decks:validate`
  - Discovers `assets/decks/*/deck.json`
  - Validates schema, coverage, file presence, and SVG safety allowlist
  - Exits non-zero on any hard error

- `npm run decks:normalize`
  - Runs strict validation first
  - Generates normalized assets + manifest into each deck `.normalized/` folder
  - Regenerates `assets/decks/decks.index.json`
  - Exits non-zero on validation failure

- `npm run decks:index`
  - Regenerates `assets/decks/decks.index.json` from normalized manifests only
